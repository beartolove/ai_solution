# CLAUDE.md — 使用習慣與專案規範

> 本檔記錄使用者的固定要求，Claude 每次協作前請先閱讀並遵守；有新要求即補充於此。

## 語言
- 一律使用**正體中文、臺灣用語**（軟體、影片、資料夾、程式碼、預設、網路、檔案）。
- 模型輸出若為簡體（Whisper 系列常見），以 OpenCC **`s2tw`**（只轉字形）轉為正體。**不可用 `s2twp`**：它會把正確的詞也換掉（連接詞→連線詞、對象→物件、發佈→釋出），2026-10-31 實測發現。用語統一交給專有名詞庫。
- 每次回應前，先考量是否有可用的 Skill 能協助。

## 文件與版控
- 專案根目錄必須維護：
  - `README.md`：操作說明，功能一有變動就同步更新。
  - `CHANGELOG.md`：依 Keep a Changelog 格式，採語意化版號（MAJOR.MINOR.PATCH）。
  - `CLAUDE.md`：本檔。
  - `VERSION`：**唯一版本來源**，程式、介面、CHANGELOG 都從這裡對齊。
- 每次修改都要遞增版號並寫入 CHANGELOG。

## 使用介面（UI）要求
- 必須兼顧 **RWD**（手機、平板、筆電、桌機）。
- **字型可放大縮小**（介面提供 A- / A / A+，並記住使用者設定）。
- **外觀可切換自動／明亮／暗黑**（0.9.6）；新增深色樣式時要同時寫「跟系統」與 `:root[data-theme="dark"]` 兩份，並以 `:root:not([data-theme="light"])` 限定系統深色規則。
- 畫面簡單直覺，以**左側可收合選單**為主要導覽。
- 主介面 **LOGO 下方顯示目前版本號**（讀取 `VERSION`）。

## 資料夾分工
- 專案程式、文件、報告：`D:\code_projects\transcribe`
- `D:\models` **只放模型**，不放任何專案檔、報告或程式。
- **媒體檔放 `D:\mediafiles`**（0.6.7 起，2026-11-01 使用者決定），避免專案複製給使用者時過大：
  - `uploads\`：每次在介面上傳的影片、聲音，**每個任務一個資料夾**（原始檔＋字幕＋純文字＋MP3＋紀錄）。
  - `benchmark\`：效能實測暫存（`benchmark_日期時間\`）。
  - `downloads\`：**從網路下載的影音**，每個任務一個資料夾（0.7.1 起，2026-11-01 使用者要求；不放 `uploads\`）。
  - 程式一律讀 `config.media_root()`，不寫死路徑；優先順序：網頁「參數設定」（`data\settings.json`）→ 環境變數 `MEDIA_ROOT` → 預設 `D:\mediafiles`。`setup.cmd` 要告知預設路徑。
  - 修改位置不自動搬移或刪除舊檔，只提示舊位置還有幾個任務。
- 留在專案內：測試錄音與標準樣本 `samples\`（連同專案預設值整包給使用者）、`env-reports\`、`glossary\`、`data\`（設定、cookies）。

## 模型選用原則
- 已採用：Breeze-ASR-25（臺灣聯發創新基地）、Whisper（OpenAI，美國）、pyannote（法國）、TranslateGemma（Google，美國）。
- **不可使用中國廠商開發的模型**（例：阿里 Qwen、SenseVoice、FunASR、Paraformer、DeepSeek、百度、騰訊、字節等）。
- 優先順序：臺灣（Breeze 系列）→ 美國／歐洲開源模型（Whisper 等）。
- 新增任何模型前，先確認開發者國別與授權。
- 本機 LLM（2026-11-01 使用者決定）：Google Gemma 4（Intel 官方 OpenVINO int4 版），依電腦記憶體建議 E2B／E4B／26B-A4B，母機用 E4B；詞庫判讀與階段 8 整理逐字稿共用同一個模型。setup.cmd 要依該電腦建議適合的大小。

## 辨識引擎
- NVIDIA ≥4GB（等級 A/B）：faster-whisper（CT2 模型）。
- 其他（等級 C/D）：**Intel OpenVINO**（openvino-genai `WhisperPipeline`），Intel 顯示卡優先、失敗自動改 CPU；做法與 mov_downloader 一致。
- OpenVINO 模型放 `D:\models\asr\ov\`；來源依序為本機 keyboard_free（`%APPDATA%\KeyboardFree\models\ov`）→ 共用來源 `MODELS_SOURCE` → 管理者 `admin-convert-openvino.cmd` 轉換。
- 不使用 whisper.cpp（0.3.1 起）。

## 效能實測（benchmark）的定位
- 目的是讓**每台電腦了解自己的最佳配置**（模型、裝置、長檔切段長度）與適合的檔案格式，不是批次轉檔。
- 快速健檢必須短（約 5–10 分鐘，用 3 分鐘標準樣本）；長檔切段測試保留，但詢問後才跑。
- 實測結果寫入 `env-reports\<電腦名稱>.benchmark.json`，轉檔程式自動採用，使用者不用手動選。

## 轉檔流程決策
- 辨識直接從原始檔（m4a、wav、mp4…）解碼 16kHz，不先轉 MP3，避免二次壓縮（2026-10-31 使用者確認）；MP3 另存一份供保存。
- 0.6.5 起：mp3／m4a／aac／ogg／opus 不另存 MP3（直接保留原檔）；wav、flac、影片才在字幕完成後另存 MP3。不可讓「轉 MP3」擋在辨識前面（2026-11-01 使用者指正）。
- 長檔自動切段、每段存檔。

## 檔名規則（0.7.1）
- 下載的影片標題一律先**簡體轉正體**（`s2tw`）再當名稱與檔名，原始標題另存。
- 所有檔名經 `app\naming.py` 處理，確保 Windows 可用：不合法字元換全形、去掉控制／零寬字元與表情符號、避開保留名稱、整條路徑 ≤ 240 字元。

## 說話者辨識（0.8.0）
- pyannote community-1，從 `D:\models\diarization\` 讀取，CPU 執行；元件第一次使用時自動安裝（2026-11-01 使用者選擇自動安裝）。
- 預設不分辨；已完成任務可補做；失敗不影響逐字稿。改名要同步更新 SRT／TXT。
- 母機實測：PyTorch CPU 耗時約為錄音長度的 0.67～0.84 倍；改用 **OpenVINO＋Intel 顯示卡（固定輸入大小）** 後約 0.05 倍（4 分 19 秒影片 173 → 14 秒），結果與 CPU 相同。第一次安裝元件約 12 分鐘。
- Intel 顯示卡跑 OpenVINO 一律用**固定輸入大小**（可變大小在 Intel 顯示卡上反而比 CPU 慢一倍）。
- 聲紋計算方式由診斷比較後存成設定 `diarize_device`；沒測過時用 OpenVINO CPU。

## 登入影片（0.10.0）
- 自帶 Chrome 擴充功能 `chrome_extension\`「逐字稿登入同步」；預設同步 YouTube／Google、FB、IG、Threads，X、Bilibili 選用。
- 先不帶 cookies，被要求登入才自動帶入重試；yt-dlp 用暫存複本（用完即刪）。
- API 只接受 `chrome-extension://` 來源，第一次同步自動配對；cookies 只存 `data\`、不寫紀錄、不打包。
- 延後：無痕視窗同步 YouTube 會員、同步到 1～3 個資料夾（4-4）。

## 雙語學習（0.9.0，2026-11-01 使用者決定）
- 任務頁兩種版面：觀看模式（字幕疊在影片下方）／學習模式（影片左、逐字稿右）。
- 第二語言只做「外文 → 正體中文」，用本機 LLM：**Google TranslateGemma 4B**（OpenVINO int8，存 `D:\models\llm\`，管理者用 Token 下載轉換一次）；譯文一律 `s2tw`。
- 第一版只做雙語對照；單句重複、播完暫停等練習功能之後再說。

## 測試與隱私（2026-11-01 使用者提醒）
- 程式一律在使用者電腦本機執行。Claude 開發測試時**不可把使用者的錄音、逐字稿或模型複製到雲端工作區**；真的需要時先詢問，或改用公開內容的錄音。

## 母機與部署
- 管理者先在母機準備好完整的 `D:\models`。發佈方式：整包複製 `D:\models` 給使用者，或設共用來源 `MODELS_SOURCE`（網芳／隨身碟）讓 setup 只複製需要的；使用者再執行 `setup.cmd` 開始所有動作。
- **模型配置方案**（0.14.0，2026-11-02 使用者決定）：專案需要哪些模型記在專案根目錄 `models.json`（開發時維護、隨程式更新；新增或更換模型時一定要同步修改）。每台依「要用的功能＋硬體＋效能實測」算出方案，存 `env-reports\<電腦名稱>.models.json`，只準備方案裡的模型；功能在 setup.cmd 第一次詢問（轉逐字稿必選），之後在網頁「參數設定 → 這台電腦」修改，改完缺的模型立刻在背景準備。
- **電腦別名**（0.14.0，使用者要求）：每台可設別名（例：辦公室筆電），介面與報告優先顯示別名，讓使用者容易辨認。
- **程式不可自動刪除使用者的模型或檔案**。用不到的模型只告知（列出路徑與原因），由使用者自行手動刪除。
- 例外：使用者在網頁上**主動按「刪除」並在確認視窗同意**後，才可刪除該任務資料夾（僅限媒體檔位置 `uploads\` 底下程式產生的檔案）。所有刪除前一定要確認（2026-10-31 使用者要求）。
- 網址下載：**下載 mp4 影片給人觀看**（H.264 優先、最高 1080p），播放以影片為主；辨識直接讀 mp4 的聲音軌，不另存暫存聲音檔、不另存 MP3（0.7.3，2026-11-01 使用者要求）。
- 網址下載時 yt-dlp 先存成 `media.*` 暫存名，完成後由程式改成正體標題；取消或失敗時只清除程式產生的未完成片段（`media.*.part`），其他檔案不動（0.7.1）。
- 分類時要分清楚：本機用不到 ≠ 已停用；只有「任何電腦都不再使用」的才標為已停用。

## 安裝原則（參考 mov_downloader）
- 只裝當下功能真的用得到的東西，並自動完成；不列一長串「必要清單」讓使用者處理。
- 唯一需要使用者手動安裝的是 Python。
- 未來階段才需要的元件（例如說話者辨識的 pyannote.audio），等第一次使用該功能時才安裝。

## 模型存放原則
- 所有 AI 模型集中存放於 `D:\models`，程式一律讀 `config.models_root()`，不寫死路徑；優先順序：網頁「參數設定」→ 環境變數 `MODELS_ROOT` → `D:\models`（0.9.7，setup.cmd 也採用網頁設定）。
- 各專案**不得自行重複下載或安裝模型**；Hugging Face 快取指向 `D:\models\.hf-cache`（`HF_HOME`）。
- 沒有 D 槽的電腦，只要把 `MODELS_ROOT` 指到其他磁碟即可。

## 測試資料
- 測試音檔放在專案 `samples\`（0.6.8 起由 `files\` 併入，2026-11-01 使用者決定；可能含內部會議內容，不進版控；不搬到 `D:\mediafiles`，部署時連同專案預設值一起給使用者）。`benchmark_` 開頭的是擷取出的標準樣本。目前 8 段：口說課程 ×2、AI 教學、亞灣論壇、09-29 會議，以及較長的門哨（10/19）、AI 成本及佐證（10/21）、AI 隨行旅伴討論（10/29）。
- 專有名詞庫放在 `glossary\`，CSV（UTF-8 BOM，方便 Excel 編輯）。誤寫本身也是常用詞的放「只提醒」欄，不自動替換（2026-11-01 使用者同意）。
- 量測專有名詞正確率：用「門哨（10/19）」錄音的前 5～10 分鐘，在網頁校對模式改成標準答案後產生報告（2026-11-01 使用者決定）。

## Hugging Face 政策
- **一般使用者不需要 Hugging Face 帳號或 Token**；需要同意條款的模型由管理者一次性下載，再從內部共用來源發佈。

## 備份（0.14.1，2026-11-02 使用者決定）
- 程式備份到 GitHub **公開**儲存庫 `beartolove/ai_solution` 的 `transcribe` 資料夾，用 `admin-backup-github.cmd`（工作複本在 `D:\code_projects\ai_solution`，專案本身不執行 git）。
- 照原樣公開（含詞庫、CLAUDE.md、ROADMAP），但**測試錄音一律不上傳**，包含 `samples\benchmark_sample.mp3`（取自內部會議）。`data\`（設定、cookies）、`env-reports\`、`.venv` 等也不上傳。
- 新增檔案時要想到它會公開：帳號、Token、內部錄音、逐字稿內容不可放進會上傳的位置。
- `D:\mediafiles`（轉檔與校對成果）、`D:\models` 不在 GitHub 備份範圍，另外複製到 NAS 或外接硬碟。

## 開發規劃
- 依 `ROADMAP.md` 階段順序進行，每完成一階段更新 ROADMAP 進度、README、CHANGELOG。
- 不協助破解 DRM；需登入的平台只用使用者本人瀏覽器的 cookies。

## 程式撰寫注意
- **OpenVINO 版本相容**（0.13.7）：模型用較新版 OpenVINO 轉出時，舊版執行環境載入會在底層當掉（攔不到、伺服器直接結束）。載入前一律經 `app\ovcompat.py` 比對；Python 至少 3.10（3.9 只能裝到 OpenVINO 2025.3），建議與母機相同的 3.11.9。2026-11-02 HQO302003 實測發現。
- **多台電腦同時開發**：在其他電腦改過程式後，要把修改併回母機，兩邊版號一致再繼續（2026-11-02 0.13.7～0.13.8 從 HQO302003 併回）。
- Windows PowerShell 5.1 呼叫外部程式（如 `python -c`）時，參數中的雙引號會被移除；內嵌程式碼不可含雙引號，或改寫成 .py 檔再執行。

## 介面分工（2026-10-31 使用者決定）
- `setup.cmd`：命令列，只負責確認／安裝執行環境。
- 使用者操作入口只有 `setup.cmd`、`start.cmd`（0.6.8 起移除 `benchmark.cmd`、`transcribe.cmd`，一致改用網頁介面；`pack-source.cmd` 也已移除，Claude 改為直接讀寫專案資料夾）。管理者另有 `admin-*.cmd`。
- 轉逐字稿、效能實測、結果解讀：一律在網頁介面（`start.cmd`）操作，結果要用白話解讀，不只列數字。
- 字幕驗收：在網頁上直接播放影片／錄音並疊字幕，支援 0.25～2 倍速與字幕開關；**這些控制必須在播放器內，全螢幕時也要能用**。
- 播放器仿 YouTube：控制列疊在畫面上、閒置自動隱藏，不另佔一排；點畫面播放／暫停。
- 版面內容置中。
- 版面：不要頂部標題列佔空間；漢堡選單在左上角，字型大小等設定收在選單內。任務頁影片在最上面，資訊、下載、逐字稿在影片下方。
- 「清除」完成的任務＝只從清單隱藏，不刪除檔案；「刪除」才會刪檔，且需確認。
- 轉檔完成要有提示音，讓使用者轉檔時可以去做別的事。
- 網頁介面色系：海霧底 #EEF3F1、深港灣青 #12343B、浮標橘 #F26B1D（只用於主要動作與進度）；系統中文字型，不依賴外部 CDN（可離線）。

## 部署環境
- 會部署到多台 **Windows** 筆電／桌機：可能沒有 GPU，或 VRAM 大小不一。
- 新電腦一律**雙擊專案根目錄的 `setup.cmd`**：自動設定模型位置 → 環境初測 → 執行環境（.venv、套件、ffmpeg）→ 辨識模型。
- 給使用者的操作方式以「雙擊 .cmd」為主，避免要求手動輸入 PowerShell 指令；腳本出錯時視窗必須停住並顯示原因。
